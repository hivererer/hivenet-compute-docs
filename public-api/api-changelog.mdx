Use this page to track changes to the Compute API that may affect scripts, tools, or integrations.

## Current API version

Production base URL:

`https://api.hivecompute.ai/v1`

Staging base URL:

`https://staging-api.hivecompute.ai/v1`

The endpoint reference covers instance creation and lifecycle, logs, usage metrics, regions, hardware presets, images, and SSH-key registration and retrieval.

## Latest changes

<Update label="November 19, 2026" description="Compute v1.39">
  ## Create instances and register SSH keys

  Added:

  - [`POST /instances`](/public-api/endpoints/create-instance) to create VMs and containers from a preset and image. A successful request returns `201` with `instance.instance_id`. Poll that ID for readiness.
  - [`GET /images`](/public-api/endpoints/list-images), with required `type=vm` or `type=container`.
  - [`POST /ssh-keys`](/public-api/endpoints/register-ssh-key), accepting public-key `content` and returning `201`.
  - [`GET /ssh-keys/{id}`](/public-api/endpoints/get-ssh-key) to retrieve a registered public key.

  Follow [Create an instance using the Compute API](/public-api/create-an-instance-using-the-compute-api) for the provisioning workflow.

  ## Changes that affect existing integrations

  - Instance list, detail, and lifecycle-action responses use the public instance record, with named status and readiness values and ISO 8601 timestamps. Action responses can contain only `instance_id` when the immediate readback is unavailable.
  - Public instance responses no longer include `user_id`, `user_name`, `user_email`, `org_id`, `org_name`, or `host_id`.
  - Preset `cpu`, `memory`, and `storage` are numeric strings without units. `hourly_price` and `price_discounted` are decimal strings without currency symbols. No preset discount is represented by `""`. Instance `hourly_rate` remains a JSON number and can contain floating-point precision artifacts.
  - `date_range_begin` and `date_range_end` filter by creation time. Instances that never started can match. Reversed ranges return `400`. Fractional seconds are discarded, and the public response does not yet expose `created_at`.
  - Malformed cursors return `400` for instance and image lists. Preset cursor validation remains inconsistent; use only the returned cursor.
  - Rate limits are now 60 requests per minute per API key, per endpoint. The metrics endpoint shares its budget across all instance IDs. Respect `Retry-After` on `429`.

  ## Integration notes

  Registering the same SSH key again creates a new ID; trailing newlines are preserved. SSH certificates and multi-line keys are rejected.

  Instance creation is not idempotent, and names can repeat. After a lost response or `500`, `503`, or `504`, check the instance list before retrying to avoid creating a second billed instance. SSH-key listing and deletion, key names and fingerprints, startup scripts, tags, and `PATCH` rename or retag operations are outside this release.
</Update>

<Update label="October 29, 2026" description="Compute v1.38">
  ## Instance usage metrics

  Added [`GET /instances/{id}/metrics`](/public-api/endpoints/get-instance-metrics) for instance usage time series. The `range` parameter is required and accepts `1h`, `6h`, `24h`, or `7d`, without case sensitivity.

  A user-bound API key can read metrics only for instances owned by that user. Requests for another user's instance return `404`, as requests for a missing instance do.
</Update>

<Update label="08/10/2026">
  ## API surface finalized for release

  **Changed**

  - Production base URL is now `https://api.hivecompute.ai/v1`.
  - Staging is available at `https://staging-api.hivecompute.ai/v1`.
  - Region values are `UAE`, `FR`, and `US`.
  - Instance logs are returned newest first. `entries[0]` is the most recent line.
  - Start, stop, and terminate can return `409 Conflict` with error code `CONFLICT` when the requested action conflicts with the current lifecycle state.
  - `500` responses use the generic message `An internal error occurred.` Clients should use `error.code`, not `error.message`, for program logic.
  - `429` responses include `Retry-After` and use the standard error envelope.

  **Removed from this release**

  - `POST /ssh-keys`
  - `GET /ssh-keys/{id}`

  SSH-key operations were excluded from that release. Registration and retrieval were added in Compute v1.39 on November 19, 2026.
</Update>

## What counts as a breaking change

A breaking change may require you to update code that already works. Examples include removing an endpoint or field, changing a field type, changing authentication behavior, or making an existing request parameter required.

<Danger>
  Don't rely on undocumented fields or behavior. Build integrations against the published API reference.
</Danger>

## How to stay compatible

- Use the versioned base URL shown in the docs.
- Build logic around documented fields and `error.code` values.
- Treat cursors as opaque.
- Respect `Retry-After` on `429` responses.
- Check instance state before retrying lifecycle actions.
- Review this changelog when integration behavior changes unexpectedly.

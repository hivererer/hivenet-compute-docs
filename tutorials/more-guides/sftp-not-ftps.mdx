## FTPS vs. SFTP at a glance

| Feature              | SFTP                  | FTPS                               |
| :------------------- | :-------------------- | :--------------------------------- |
| Default port         | 22                    | 21 (control) / 990 (implicit)      |
| Encryption layer     | Built‑in (SSH)        | TLS/SSL on top of FTP              |
| Authentication       | SSH keys or passwords | X.509 certs or passwords           |
| Firewall friendly    | ✅ Single port         | 🚧 Multiple ports (control + data) |
| Supported on Compute | **Yes**               | **No**                             |

## Why we chose SFTP

1. **Same key, same port** – Your SSH key doubles for file transfers; no extra credentials.
2. **Network access** – SFTP reuses the instance’s SSH route. Your network must allow the direct host and port or the proxy entry shown in the console.
3. **End‑to‑end encryption** – Data and commands are encrypted by default.

<Info>
  **Good to know: **FTPS requires opening a range of data ports, which conflicts with Compute’s default security posture.
</Info>

## Serve files over HTTPS

To make files available for download in a browser, see [Serve an HTTPS site](/documentation/connectivity/https-site-ssh-port-forwarding). For uploads to your instance, use SFTP.

##  Migrating scripts from FTPS to SFTP

Save the instance’s complete SSH configuration under an alias, such as `hivenet`. From the local folder containing your file, run:

```text
sftp hivenet
```

At the `sftp>` prompt, enter `put file.zip`. Use `get file.zip` to download it again. See [Transfer files with SFTP](/documentation/file-transfer/transfer-files-sftp) for graphical clients and folder transfers.

For automated workflows, tools like `rsync` or `scp` provide shell‑friendly, encrypted transfers.

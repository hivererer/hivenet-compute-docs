This guide takes you from the Compute console to a working inference request. You’ll choose a model and variant, configure fixed or autoscaling capacity, deploy it, create an API key, and use the generated quick-start snippet to call the endpoint.

<Info>
  ## What you’ll need

  - A Compute account
  - Access to a Compute organization
  - Enough credits in the organization balance for the deployment you choose
  - Python, Node.js, or a terminal with `curl` if you want to test the endpoint locally

  Inference API uses the same organization balance as your Compute resources.
</Info>

<Steps>
  <Step title="Open Inference API">
    1. Sign in to the [Compute console](https://console.hivecompute.ai/).
    2. Confirm the organization shown in the upper-left corner.
    3. Open **Inference API** from the left sidebar.
    4. Select **New deployment**.

    Deployments and API keys belong to the active organization.
  </Step>
  <Step title="Choose a model">
    The deployment page starts with the model catalog.

    Use the filters at the top to narrow the catalog by:

    - Location
    - Use case
    - Model provider

    Then select a model card to open its variants and technical details.

    A model card can show a short description, capability tags, and a starting price. The selected model panel can also show details such as GPU and quantization, context window, time to first token, inter-token latency, output speed, and license.

    <Info>
      The selected location affects which models and variants can currently be deployed. The live console is the source of truth for availability.
    </Info>
  </Step>
  <Step title="Choose a variant">
    Select the variant that best matches your workload.

    Variant cards can distinguish configurations by cost, performance, context size, GPU setup, or another serving characteristic. Review the technical details shown below the variants before continuing.

    If a model or configuration is unavailable in the selected location, choose another available option or location.
  </Step>
  <Step title="Choose fixed or autoscaling capacity">
    Under **Capacity replicas**, decide how the deployment should keep serving capacity available.

    For **fixed capacity**:

    1. Leave **Autoscale replicas** off.
    2. Set the total number of replicas you want running.

    Each replica is one serving copy of the selected model variant. More replicas increase request capacity and increase the hourly cost.

    For **autoscaling**:

    1. Turn on **Autoscale replicas**.
    2. Set **Reserved** to the number of replicas you want always running.
    3. Set **Burst limit** to the highest replica count Hivenet may scale toward when traffic needs more capacity.

    Reserved replicas are billed continuously while the deployment runs. Burst replicas are best effort and are billed only while active.

    <Note>
      Burst capacity depends on available infrastructure. Requests above currently running capacity can queue while an additional replica starts.
    </Note>
  </Step>
  <Step title="Name the deployment">
    Keep the suggested name or enter your own.

    Use lowercase letters, numbers, and hyphens. Deployment names must be unique within the organization.

    The deployment name is only a management label. It is not necessarily the model value used in API requests.
  </Step>
  <Step title="Review the setup and deploy">
    Check the **Review your setup** section before you continue.

    It shows the selected model, location, capacity configuration, and current estimates for:

    - Total cost per hour
    - Cost per 24 hours
    - Cost per week

    If the organization does not have enough credits, the console shows a warning and a link to add credits.

    Select **Deploy model** when you’re ready.

    The deployment appears under **Deployments** with **Starting** status while Hivenet prepares it. Starting a model can take up to 10 minutes. Charges begin once serving capacity is running.
  </Step>
  <Step title="Create an API key">
    If the organization does not already have a key you want to use:

    1. In **API keys**, select **New key**.
    2. Enter a label.
    3. Create the key.
    4. Copy the full secret immediately and store it securely.
    5. Close the dialog only after you have saved it.

    <Warning>
      The full API key is shown once. If you lose it, create another key and update your application.
    </Warning>
  </Step>
  <Step title="Open the deployment details">
    When the deployment is ready, open **Details** from its menu.

    The details dialog can show:

    - Endpoint URL
    - Model
    - GPU and quantization
    - Context window
    - License
    - Region
    - Cost so far
    - Creation time
    - Replica configuration and recent replica activity
    - Request, latency, token, and output-speed metrics
    - Quick-start snippets for Python, JavaScript, and `curl`

    <Warning>
      Copy the endpoint URL exactly as shown. It already contains the API version path, such as `/v1`. Do not add another `/v1`.
    </Warning>
  </Step>
  <Step title="Send your first request">
    The safest approach is to copy one of the generated **Quick-start snippets** from the deployment details. It contains the endpoint structure and model value expected by that deployment.

    For Python, install the OpenAI SDK:

    ```bash
    pip install openai
    ```

    Then use the values from your deployment:

    ```python
    from openai import OpenAI
    
    client = OpenAI(
        base_url="YOUR_ENDPOINT_URL",
        api_key="YOUR_INFERENCE_API_KEY",
    )
    
    response = client.chat.completions.create(
        model="YOUR_SERVED_MODEL_NAME",
        messages=[
            {"role": "user", "content": "Hello!"}
        ],
    )
    
    print(response.choices[0].message.content)
    ```

    Or use `curl`:

    ```bash
    curl YOUR_ENDPOINT_URL/chat/completions \
      -H "Authorization: Bearer YOUR_INFERENCE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "YOUR_SERVED_MODEL_NAME",
        "messages": [{"role": "user", "content": "Hello!"}]
      }'
    ```

    <Tip>
      Do not substitute the deployment name for the `model` value. Copy the value generated by the console.
    </Tip>
  </Step>
</Steps>

## After your first request

The Inference API page gives you a combined view of keys, deployments, and recent service metrics.

From a deployment, you can:

- Open **Details**
- Open **Logs** for recent deployment logs
- Change fixed or autoscaling replica settings
- Stop a deployment
- Start a stopped deployment when credits and capacity allow
- Retry replicas for a **Partially running** or **Error** deployment when the action is available
- Terminate a deployment permanently
- Remove a terminated deployment from the list

Logs cover the past hour. For deployments with more than one replica, the logs dialog lets you choose the replica to inspect. You can also search and download the displayed logs.

## Troubleshooting

### A model or configuration is unavailable

Availability depends on location and current infrastructure capacity. Change the location or choose another available model or variant.

### The deployment is still Starting

Starting a model can take up to 10 minutes. Wait for serving capacity to become available before sending production traffic.

### Autoscaling is not reaching the burst limit

Burst replicas are best effort. They depend on available infrastructure and take time to start. Requests can queue while capacity is being added.

### The API request returns an authentication error

Check that you are using an active **Inference API key** from the same organization as the deployment. A disabled or revoked key cannot authenticate requests.

### The API request cannot find the model

Use the exact `model` value from the deployment’s generated quick-start snippet. Do not assume it matches the deployment name.

### The organization does not have enough credits

Add credits before deploying or starting the model. If you cannot manage the organization balance yourself, ask the organization Owner to add credits.

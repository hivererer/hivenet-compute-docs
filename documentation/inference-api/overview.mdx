Hivenet Inference API lets you deploy open-weight models as managed API endpoints without setting up and operating the inference serving stack yourself.

You choose a location, model, model variant, replica count, and endpoint name in the Compute console. Hivenet provisions the serving infrastructure and gives you an endpoint that works with OpenAI-compatible clients such as the OpenAI SDK and `curl`.

<Info>
  Hivenet Inference API is part of the Compute console. Endpoints and API keys belong to the active organization and use the same organization credit balance as Compute resources.
</Info>

## How an endpoint is configured

The production deployment flow brings together five choices:

- **Location:** Where the endpoint runs and where requests are processed. The selected location applies to the endpoint you are creating.
- **Model:** The open-weight model you want to serve.
- **Variant:** A preconfigured serving setup that can define GPU configuration, quantization, context window, performance characteristics, and price.
- **Replicas:** The number of serving replicas you want to keep running.
- **Endpoint name:** The label you use to find and manage the endpoint in the console.

Choosing a location comes first. The console then shows the models and variants available for that location.

## Fixed replica capacity

A **replica** is one serving copy of the selected model variant. More replicas provide more request capacity and increase the endpoint's hourly cost.

The current production version uses a fixed replica count. You choose how many replicas to run and can change that number later when capacity is available.

<Note>
  Autoscaling is not available in the current production version. Use the replica control to choose the fixed number of replicas you want to run.
</Note>

## Inference API, Compute, and Hivenet Router

These products solve different parts of the inference stack.

| Product | Use it when | You manage |
| --- | --- | --- |
| **Hivenet Inference API** | You want a managed model endpoint for an application or service. | Your model choice, location, replicas, API keys, and client code. |
| **Compute with Hivenet** | You want direct GPU or CPU infrastructure and control over the serving environment. | The instance, runtime, model server, configuration, and operations. |
| **Hivenet Router** | You want to run Hivenet's open-source model-routing software on infrastructure you control. | The router deployment, model backends, infrastructure, and operations. |

If you need an API endpoint and do not want to operate vLLM or another serving runtime yourself, Hivenet Inference API is the managed path.

## Endpoint states

The Inference API page shows the current state of each endpoint.

| Status | What it means |
| --- | --- |
| **Starting** | Hivenet is preparing the endpoint. It is not ready to serve requests yet. |
| **Running** | The endpoint is serving requests. |
| **Partially running** | Some requested replicas are running while others are unavailable or recovering. |
| **Stopped** | The endpoint is offline but can be started again when capacity and credits allow. |
| **Error** | The endpoint is not currently serving. A **Retry** action can appear when recovery is possible. |
| **Terminated** | The endpoint has been permanently shut down and cannot be started again. |

Starting a model takes about 90 seconds in the current production flow. Charges begin once it is running.

<Warning>
  **Stop** is reversible. **Terminate** permanently shuts down the endpoint, makes its URL unusable, and cannot be undone.
</Warning>

## Endpoint details and metrics

Open an endpoint's details to see its serving information. Depending on its state, the view can include:

- Endpoint URL
- Model
- GPU and quantization
- Context window
- License
- Region
- Cost so far and current hourly rate
- Replica count
- Requests per hour
- Inter-token latency
- Tokens in and out over 24 hours
- Output speed
- Quick-start snippets for Python, JavaScript, and `curl`

The endpoint URL can also be copied directly from the deployment list.

## API keys

Inference API keys are scoped to the organization rather than to a single endpoint. One active key can authenticate requests to the organization's inference endpoints.

When you create a key, the full secret is shown once. Save it before closing the dialog. You won't be able to view that full secret again.

You can:

- **Disable** a key temporarily and re-enable it later.
- **Revoke** a key permanently.

Disabling or revoking a key stops requests made with that key. It does not stop running endpoints or their charges.

## Billing

Inference API draws from the same prepaid organization credit balance as Compute.

Before deployment, the review section shows the current estimated hourly, 24-hour, and weekly cost for the selected model, location, and replica count.

Each running replica contributes to the endpoint's hourly cost. Stopping or terminating an endpoint stops its serving charges once its replicas have shut down.

See [Understand Inference API billing](/documentation/inference-api/billing) for the full billing model.

## Location, capacity, and data handling

Location is selected before the model in the current production flow. The console can mark a location **Sold out** when it cannot accept another endpoint.

The location screen also explains how prompts and responses are handled for the location you select. For example, when France is selected, the production UI states that prompts and responses are processed and stored in France, with EU data residency, and are not used by Hivenet to train models.

<Info>
  Read the location notice shown in the console before deploying. The notice is the source of truth for the data-handling statement associated with that location.
</Info>

Capacity can also limit how many replicas you can run for a selected model variant. The console is the source of truth for what can be provisioned now.

## OpenAI-compatible requests

Each endpoint publishes an endpoint URL and an exact served model name. Use both values from the endpoint's **Quick-start snippets**.

<Warning>
  Copy the endpoint URL exactly as the console shows it. The URL already includes its API version path, such as `/v1`. Do not append another `/v1`.
</Warning>

The served model name can differ from the catalog title or your endpoint name. Copy the `model` value from the generated snippet rather than typing it from memory.

Use the **Deployments** section of Inference API to monitor and manage the model endpoints your organization has created.

Each row shows the endpoint status, name, model, region, replica count, recent request count when available, and current hourly cost.

## Open endpoint details

Open an endpoint's options menu and select **Details**.

Depending on the endpoint state, the details view can include:

- Endpoint URL
- Model
- GPU and quantization
- Context window
- License
- Region
- Cost so far and current hourly rate
- Created or stopped time
- Replica count
- Requests per hour
- Inter-token latency
- Tokens in and out over 24 hours
- Output speed
- Quick-start snippets for Python, JavaScript, and `curl`

You can also copy the endpoint URL directly from the Deployments list.

## Endpoint states

| State | What it means |
| --- | --- |
| **Starting** | Hivenet is preparing the endpoint. It is not ready to serve requests yet. |
| **Running** | The endpoint is serving requests. |
| **Partially running** | Some requested replicas are serving while others are unavailable or recovering. The endpoint can still accept traffic with reduced capacity. |
| **Stopped** | The endpoint is offline, but its configuration is kept so it can be started again later. |
| **Error** | The endpoint is not currently serving. A **Retry** action can appear when recovery is possible. |
| **Terminated** | The endpoint has been permanently shut down and cannot be started again. |

The console says starting a model takes about 90 seconds.

## Stop an endpoint

Use **Stop** when you want to take an endpoint offline without deleting its configuration.

1. Open the endpoint's options menu.
2. Select **Stop**.
3. Review the confirmation.
4. Select **Stop model**.

The endpoint stops serving requests and its replicas are shut down. Serving charges stop once the endpoint reaches **Stopped**.

<Info>
  Starting the endpoint again still depends on enough capacity being available in the same location.
</Info>

## Start a stopped endpoint

1. Open the options menu for a **Stopped** endpoint, or open its details.
2. Select **Start** or **Start model**.
3. Review the confirmation.
4. Confirm the start.

The endpoint moves to **Starting** and begins serving again when it reaches **Running**.

Starting can be blocked if the organization does not have enough credits or the required capacity is unavailable.

## Retry a failed endpoint

A **Retry** action can appear when an endpoint is **Partially running** or in **Error**.

Retry asks Hivenet to recover the failed serving replicas. It does not start an endpoint that you deliberately stopped; use **Start** for a **Stopped** endpoint.

If Retry is unavailable or repeatedly fails, see [Troubleshoot Hivenet Inference API](/documentation/inference-api/troubleshooting).

## Terminate an endpoint

Use **Terminate** only when you no longer need the endpoint. Termination is permanent.

1. Open the endpoint's options menu.
2. Select **Terminate**.
3. Review the confirmation checklist.
4. Confirm that you understand the endpoint will stop serving and cannot be restored.
5. Select **Permanently terminate**.

After termination:

- The endpoint stops accepting requests.
- Its URL is no longer usable.
- It cannot be started again.
- Serving charges stop once termination is complete.
- The terminated entry remains visible until you clear it.

<Warning>
  Update any application that depends on the endpoint before terminating it. Termination cannot be undone.
</Warning>

## Clear a terminated endpoint

**Clear** removes an already-terminated entry from the Deployments list.

1. Open the options menu for a **Terminated** endpoint.
2. Select **Clear**.
3. Review the confirmation.
4. Select **Clear model**.

Clearing is only a list-cleanup action. It does not terminate a running or stopped endpoint.

## Change replica count

For a running endpoint, use **Edit** beside the replica count in the details view to change fixed serving capacity when additional capacity is available.

See [Manage replicas and capacity](/documentation/inference-api/replicas-and-capacity) for the scaling behavior and cost implications.

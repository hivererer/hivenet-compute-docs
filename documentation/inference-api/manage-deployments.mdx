Use the **Deployments** section of Inference API to monitor and control the models your organization has deployed.

Each row can show the deployment status, name, model, location, replicas, recent request count, current hourly cost, and actions that apply to its current state.

## Open deployment details

Open a deployment's options menu and select **Details**.

The details dialog can include:

- Endpoint URL
- Model
- GPU and quantization
- Context window
- License
- Region
- Cost so far
- Creation time
- Fixed or autoscaling replica configuration
- Recent replica activity
- Requests per hour
- Inter-token latency
- Tokens in and out over 24 hours
- Output speed
- Quick-start snippets for Python, JavaScript, and `curl`

Some metrics can be empty while the deployment is starting or before it has served traffic.

## Deployment states

| State | What it means | Typical actions |
| --- | --- | --- |
| **Starting** | Hivenet is preparing the deployment. | View details or logs and wait for capacity to come online. |
| **Running** | The deployment is serving requests. | View details, logs, edit capacity, stop, or terminate. |
| **Partially running** | Some expected replicas are serving and others are not. | View details and logs, retry when available, edit capacity, stop, or terminate. |
| **Stopped** | The deployment is offline but its configuration is retained. | Start or terminate. |
| **Error** | No replicas are currently serving. | View details and logs, retry when available, or terminate. |
| **Terminated** | The deployment has been permanently shut down. | View details or logs and remove it from the list. |

The UI may briefly pass through transitional states while an action is being processed, but the table above reflects the customer-facing states shown in the current V2 design.

## View deployment logs

Select **Logs** for a deployment when the action is available.

The logs dialog shows logs from the **past hour**. You can:

- Search within the displayed logs
- Download the logs
- Switch between replicas when the deployment has more than one replica

The console also handles cases where logs are unavailable because the deployment is not running, the log request timed out, no logs were returned, or the log service could not be reached.

<Tip>
  For a **Partially running** or **Error** deployment, logs are one of the first places to check before retrying or changing capacity.
</Tip>

## Stop a deployment

Use **Stop** when you want to take a deployment offline but may need the same configuration again.

1. Open the deployment options menu.
2. Select **Stop**.
3. Review the confirmation.
4. Confirm the action.

The endpoint stops serving once the deployment has shut down its running replicas.

Stopping preserves the deployment configuration, but starting it again still depends on enough credits and capacity being available.

## Start a stopped deployment

You can start a **Stopped** deployment from the deployment list or its details view.

Before the start proceeds, the console checks whether the organization has enough credits. If it does not, you are directed to add credits first.

After a successful start request, the deployment returns to **Starting** while Hivenet prepares serving capacity.

## Retry a partially running or failed deployment

A **Retry** action can appear for **Partially running** and **Error** deployments.

Use it when you want Hivenet to retry replicas that are not currently serving. Whether retry succeeds still depends on the underlying condition, including available infrastructure.

If retry is unavailable, the console can show a tooltip explaining why.

## Edit replicas

Open **Details** and select **Edit** next to **Replicas**.

You can switch between:

- Fixed replica count
- Autoscaling with **Reserved** and **Burst limit** values

See [Manage replicas and capacity](/documentation/inference-api/replicas-and-capacity) for the full explanation.

## Terminate a deployment

Termination permanently shuts down the deployment.

1. Open the deployment options menu.
2. Select **Terminate**.
3. Review each consequence in the confirmation dialog.
4. Confirm that your application no longer needs the endpoint.
5. Select **Terminate deployment**.

The confirmation makes clear that:

- Requests to the endpoint fail after termination.
- The endpoint URL is no longer usable.
- Charges stop once termination is complete.
- The action cannot be undone.

<Warning>
  Update any application that depends on the endpoint before terminating it.
</Warning>

## Remove a terminated deployment

Termination and removal are separate actions.

After a deployment is **Terminated**, select **Remove** if you want to clear that terminated record from the deployments list.

Removing the record does not terminate a running deployment. The deployment must already be terminated before **Remove** is available.

Inference API keys authenticate requests to your organization's model deployments.

Keys are managed from the **API keys** section of the Inference API page. They are scoped to the active organization rather than to a single deployment.

## Create a key

1. Open **Inference API** in the Compute console.
2. In **API keys**, select **New key**.
3. Enter a label that helps you recognize what the key is used for.
4. Create the key.
5. Copy the full secret immediately and store it somewhere secure.

<Warning>
  The full secret is shown only when the key is created. Save it before closing the dialog. If you lose it, create a new key and update the application that uses it.
</Warning>

After creation, the API keys table shows a masked version of the key together with information such as:

- Status
- Label
- Masked key
- Creator
- Last used
- Created date

## Use the key in a request

Pass the key as a bearer token when calling your deployment endpoint.

```bash
-H "Authorization: Bearer YOUR_INFERENCE_API_KEY"
```

The deployment details also provide generated Python, JavaScript, and `curl` quick-start snippets.

See [Call your Inference API endpoint](/documentation/inference-api/call-your-endpoint) for complete examples.

## Disable a key

Disable a key when you want to stop it from authenticating requests without deleting it permanently.

1. Open the key's options menu.
2. Select **Disable**.
3. Confirm the action.

Requests made with that key stop authenticating after the key is disabled.

Disabling a key does not stop any deployment. Running model capacity continues to use organization credits.

## Re-enable a key

A disabled key can be made active again.

1. Open the disabled key's options menu.
2. Select **Re-enable**.

Applications using the same stored secret can authenticate again once the key is active.

## Revoke a key

Revoke a key when it should never be usable again.

1. Open the key's options menu.
2. Select **Revoke**.
3. Review the confirmation.
4. Confirm the revocation.

Revocation is permanent. Create a new key if the application needs replacement credentials.

<Warning>
  Revoke a key immediately if you believe its secret has been exposed. Then update every application or service that used it.
</Warning>

## Key management practices

- Give keys labels that identify the application, environment, or purpose.
- Keep secrets out of source code and public repositories.
- Store keys in environment variables or a secrets manager.
- Use different keys where independent revocation would be useful.
- Disable a key for temporary access changes; revoke it when access should end permanently.
- Review **Last used** when checking whether an old key is still needed.

## Keys and organizations

Keys belong to the organization in which they were created.

When working with multiple Compute organizations, confirm the active organization before creating a key or troubleshooting authentication. Use an Inference API key from the same organization as the deployment you are calling.

## Troubleshoot authentication

If a request is rejected:

1. Confirm you copied the complete key secret when it was created.
2. Check that the key status is **Active**.
3. Confirm the request uses `Authorization: Bearer ...`.
4. Confirm the key and deployment belong to the same organization.
5. Check that you are calling the deployment's Inference API endpoint, not the Compute public API.

If the secret has been lost, revoked, or exposed, create a new key rather than trying to recover the old secret.

Replicas are parallel copies of your model endpoint. They let an endpoint handle more work at the same time, but each replica adds to the hourly cost.

The current production version uses a **fixed replica count**. You choose the initial count during deployment and can change it later when capacity is available.

## How replica count affects an endpoint

An endpoint tracks the number of replicas you asked Hivenet to run and how many are currently available.

When all requested replicas are serving, the endpoint is **Running**. If fewer replicas are available, it can become **Partially running** and continue serving with reduced capacity.

## Choose the initial replica count

After selecting a model variant, choose how many replicas to run.

The console shows the expected request capacity and hourly cost for the selected replica count. The normal selector can offer up to four replicas, subject to the capacity available for that variant and location.

<Info>
  Replica availability is live. The console is the source of truth for how many replicas can currently be provisioned.
</Info>

## Change the replica count

For an endpoint that can be scaled:

1. Open the endpoint details.
2. Find **Replicas**.
3. Select **Edit**.
4. Choose the new replica count allowed by the console.
5. Save the change.

The endpoint reconciles toward the new count. Its hourly cost changes with the number of replicas being run.

## Autoscaling is not available yet

The current production version does not automatically change replica count in response to traffic.

You choose a fixed count manually. If you want to take the endpoint fully offline, use **Stop** instead of trying to reduce replicas to zero.

## Partially running endpoints

If some requested replicas fail or are unavailable, the endpoint can show **Partially running**.

The endpoint remains usable, but available throughput is lower. The deployment list can also show a **Retry** action when failed replicas can be retried.

Depending on your workload, you can:

- Retry failed replicas when the action is available
- Reduce the replica count
- Keep the endpoint running with reduced capacity
- Stop the endpoint and start it again later

## Capacity can change

Regional capacity is shared and can change while you are creating or editing an endpoint.

A replica count that was available earlier may no longer be available when you try to save a change. If that happens, use the count offered by the console or try again later.

## Replica count and billing

Each running replica contributes to the endpoint's hourly cost.

Increasing replicas raises the hourly rate. Reducing replicas lowers it after the change takes effect. Stopping the endpoint tears down its replicas and stops serving charges once the endpoint reaches **Stopped**.

See [Understand Inference API billing](/documentation/inference-api/billing) for the full billing lifecycle.

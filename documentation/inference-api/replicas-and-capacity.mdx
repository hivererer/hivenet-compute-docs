Replicas are serving copies of your selected model variant. They determine how much request capacity your deployment keeps available and how much serving capacity you pay for.

Hivenet Inference API supports both **fixed** and **autoscaling** replica configurations.

## Fixed capacity

With autoscaling turned off, you choose the total number of replicas to keep running.

For example, a fixed deployment configured with three replicas aims to keep three replicas serving while the deployment is running.

Use fixed capacity when you want predictable serving capacity and cost.

## Autoscaling capacity

Turn on **Autoscale replicas** when you want a stable baseline with room to scale above it.

Autoscaling uses two values:

- **Reserved:** Replicas that stay running while the deployment is active. This is your always-on capacity.
- **Burst limit:** The highest replica count Hivenet may scale toward when traffic requires more capacity.

If Reserved is 2 and Burst limit is 3, the deployment keeps two replicas running and can add a third when needed and available.

<Info>
  Burst replicas are best effort. They depend on available regional capacity and take time to start.
</Info>

Requests above the capacity currently running can queue while another replica starts. The console does not imply that autoscaling is instantaneous or that every burst replica is always available.

## Capacity shown in the console

The deployment configuration shows estimated request capacity alongside replica levels. Treat these figures as planning guidance for the selected model variant and request profile rather than as a universal hard request limit.

Actual serving behavior depends on factors such as:

- Model and variant
- Input and output length
- Request concurrency
- Multimodal inputs
- Reasoning or agentic workloads

The live console remains the source of truth for the capacity configuration you can order.

## Change capacity after deployment

For a deployment whose capacity can be edited:

1. Open **Details**.
2. Find **Replicas**.
3. Select **Edit**.
4. Choose fixed or autoscaling capacity.
5. Adjust the allowed replica values.
6. Select **Save**.

For fixed capacity, change the total number of replicas.

For autoscaling, adjust **Reserved** and **Burst limit** separately.

The console updates the displayed capacity and cost information as you change the configuration.

## Live regional limits

Capacity can change between deployment creation and a later edit. If the selected region no longer has room for the capacity you request, the console can limit the available values or reject the change.

A stopped deployment can also fail to start if the required capacity is no longer available.

## Partially running deployments

A deployment can show **Partially running** when fewer replicas are serving than the current capacity configuration expects.

The endpoint can still serve requests through the replicas that are available, but throughput can be lower.

When the console exposes **Retry**, you can ask Hivenet to retry failed replicas. You can also review **Logs** for recent deployment activity and errors.

Depending on the situation, you may choose to:

- Wait for recovery
- Retry failed replicas
- Reduce the fixed or reserved capacity
- Stop the deployment and start it later

## Replica activity

Deployment details can show recent replica count over time.

For autoscaling deployments, this helps you see when the service moved above or below the reserved baseline. The details view can also explain recent scaling activity, such as a replica being removed after demand fell below the scaling threshold.

## Capacity and billing

Fixed and autoscaling capacity are billed differently:

- **Fixed:** Running replicas contribute to the deployment's current hourly cost.
- **Reserved:** Reserved replicas are billed continuously while the deployment is running.
- **Burst:** Burst replicas are billed only while active.

Stopping or terminating the deployment removes serving capacity and stops those charges once the running replicas have shut down.

See [Understand Inference API billing](/documentation/inference-api/billing) for the full billing model.

A practical FAQ for running workloads on **Compute with Hivenet**. It covers billing, instances, templates, networking, and inference. If you’re new, start here. If you’re stuck, jump to **Troubleshooting** at the end.

## Billing and pricing

### How does billing work?

Compute uses **pre‑paid credits** (in euros) with **per‑second billing**. You add credits first, then start instances. Your balance decreases while instances run.

### What’s the minimum balance to start an instance?

Have at least **one hour** of credit for your chosen configuration. If your balance is lower, add funds or select a smaller instance.

### Are there hidden fees?

No. You **only pay for compute time**. Storage attached to your on‑demand instance and network traffic are included.

<Note>
  Auto top‑up is available after your first purchase. Set a threshold and amount so your balance refills before it hits zero.
</Note>

### What happens if I run out of credits?

As the organization balance runs low, Compute instances may stop or be terminated. Top up ahead of time or enable auto top-up. Running Inference API endpoints with a nonzero effective cost stop at zero credits; fully discounted endpoints with an effective cost of €0 are not stopped solely for that reason. See [Billing information](/documentation/account-billing/billing-info).

### How is storage billed?

For on‑demand instances, storage is included with your instance. All storage is **NVMe SSD**. If you need more space or options, contact support.

### Where can I find invoices and payment history?

Invoices and transaction history are available via **Stripe**. You can access your billing records from the **Billing** tab in the console.

## Instances and lifecycle

### Are Compute instances containers or virtual machines?

You can choose. Compute instances are not limited to a single runtime type. Depending on your setup, an instance can run as a container or as a virtual machine. Containers cover most workflows like running scripts, apps, and models. Virtual machines are available for use cases that require full OS-level control, kernel access, or custom images.

### Can I stop and start an instance later?

Yes. You can [**stop an instance and start it again**](/documentation/essentials/start-stop-instances) without losing your environment. Your files, packages, and configuration remain intact. Stopping releases the underlying capacity back to the pool. When you start again, availability depends on demand, and you may be placed on different hardware.

<Warning>
  **Important:** Stopped instances are not kept indefinitely.<br />If an instance remains stopped for more than 10 days, it is automatically terminated. Once terminated, the instance and its data cannot be recovered.
</Warning>

<Note>
  Stop/Start currently has **no extra fee**. This may change; always check the latest pricing.
</Note>

### Do I keep the same GPU when I stop and start?

No. Stop/Start preserves your environment, but it doesn’t reserve the underlying GPU. When you start again, Compute allocates whatever matching capacity is available in that region. If nothing matches, you’ll be asked to try again later.

### What happens to errored instances?

Compute retries failed starts a limited number of times. If the instance reaches an error state, use the retry action when the console offers it. If it keeps failing, contact Support with the instance ID, error, and approximate time. Do not use an errored instance as a backup; download important files when access is available.

If you’re not sure why the instance failed, check the instance logs in the app. They usually give enough context to understand what went wrong or what to try next.

### Is there a time limit on how long an instance can run?

There’s no fixed time limit. An instance can run as long as it stays healthy and your balance covers the runtime. In rare cases, we may need to schedule maintenance that requires a restart.

### Do my files persist when stopped?

Yes. Your environment is preserved when you stop an instance. Termination (manual or due to low balance) ends the session; use a template or image to recreate your setup quickly.

### What operating systems and images are available?

For container-based instances, choose from the templates currently shown in the console, or use a custom template. The former self-managed vLLM product flow has been retired. For managed model serving, use [Hivenet Inference API](/documentation/inference-api/overview).

For virtual machine instances, you can choose a full operating system image such as **Ubuntu**, **Fedora**, or **Debian**.

### What are custom templates?

A [**custom template**](/documentation/essentials/custom-templates) saves your configured environment (OS, packages, dependencies, and settings) so you can relaunch the same stack quickly. It’s ideal for repeatable experiments or team workflows.

## Inference and APIs

### Do you support an OpenAI‑compatible API?

Yes. [Hivenet Inference API](/documentation/inference-api/overview) provides managed, OpenAI-compatible endpoints. Use the endpoint URL, model name, and Inference API key from your deployment’s connection details.

### Can I tune inference settings?

Choose a model and serving variant for your workload, then set its fixed replica count. Available settings depend on the model and variant. See [Models and variants](/documentation/inference-api/models-and-variants) and [Call your endpoint](/documentation/inference-api/call-your-endpoint).

## Networking and access

### How do I expose my service?

Enable the required **HTTPS**, **TCP**, or **UDP** connection option when creating your instance, then use the address in its connection details. Managed Inference API deployments have their own endpoint URLs.

### Can I use SSH?

Yes. Wait for **Running**, which means the instance has responded over SSH, then use the username and SSH command shown in its connection details. An application inside the instance may still be starting. See [SSH configuration and host verification](/tutorials/more-guides/SSH-config-file-explained).

## Providers, regions, and reliability

### What provider options are available?

**Hive‑Certified providers** are available now, offering dedicated hardware and a **99.9% uptime SLA**. A broader **Spot** **Providers** tier for cost‑sensitive use cases is planned.

### How does Compute with Hivenet operate?

Hivenet runs on a **distributed cloud** backed by real devices and certified providers, rather than traditional centralized data centers. This design aims for efficiency and resilience.

## Security and data

### What are Hivenet‑Certified providers?

Hivenet‑Certified providers are audited hosts that run **dedicated machines** in controlled locations and agree to our security, privacy, and uptime standards (including a 99.9% uptime SLA).

### How are my workloads isolated from others?

Each instance runs in its own isolated environment with dedicated GPU and storage on the selected host. Certified providers operate single‑tenant machines per customer session to reduce cross‑tenant risk.

### Can a host or provider inspect my data?

No. Certified providers are **contractually prohibited** from inspecting user data or workload content. Operational telemetry (like health metrics) may be collected for reliability, but hosts can’t read your files, prompts, or model outputs.

### Do you encrypt data in transit and at rest?

- **In transit:** Public endpoints (e.g., inference over HTTPS) enforce TLS. Use HTTPS clients by default.
- **At rest:** Storage lives on NVMe disks attached to the host. If you need strong, documented guarantees, use **application‑level encryption** or self‑encrypting volumes and contact support for current provider‑level controls and attestations.

<Tip>
  Never store long‑lived secrets unencrypted on disk. Prefer environment variables, short‑lived tokens, or a secrets manager you control.
</Tip>

### How should I handle secrets (API keys, tokens) on instances?

Use environment variables or mounted files with restricted permissions, rotate keys regularly, and avoid committing secrets to images or templates. For team workflows, script secret injection at start‑up rather than baking credentials into templates.

### Do you log or store prompts/model inputs by default?

Compute records VM serial-console output, which Support can review for boot and crash troubleshooting. Data your software writes to that console can therefore appear in support diagnostics. Avoid writing secrets or sensitive payloads there, and contact Support if you need details about log access or retention.

### Can my data stay in a specific country or region (e.g., EU)?

Yes. Pick a **region** when launching. Runs and attached storage remain in that region. For compliance reviews, document your chosen region(s) in your internal data maps.

### What security documentation can you share (e.g., GDPR posture, audits)?

We can provide current security and privacy docs on request. If you require formal certifications or DPAs, contact support, and we’ll share what’s available under the appropriate terms.

### What happens to my data after termination—any data remanence guarantees?

Terminating an instance ends the session and detaches its storage. For sensitive projects, store data in encrypted volumes you control and wipe/rotate credentials at the end of a run.

### How do I report a security issue or incident?

Click on **Chat with us** in your dashboard or email [**support@hivenet.com**](mailto:support@hivenet.com) with "Security" in the subject. Include affected instance IDs, region, timestamps (UTC), and a short description. For urgent outages, also [post in the community channel](https://discord.com/cTmPDPrMG2) for faster visibility.

## GPUs and performance

### Which GPUs can I rent?

Compute currently offers **NVIDIA RTX 5090** GPU instances. Each RTX 5090 provides 32 GB of GDDR7 VRAM. Multi-GPU configurations are available when capacity allows.

The RTX 4090 fleet has been retired and is no longer available for new Compute workloads.

Availability and preset specifications can vary by location, so check the creation screen for the GPU count, vCPU, RAM, disk, bandwidth, and price you can launch now. See [GPU types and sizes](/documentation/reference/gpu-types) for more guidance.

### Where can I find GPU performance comparisons?

Our older benchmark articles include results from hardware that was available when the tests were run, including RTX 4090 systems. Keep the publication date and tested configuration in mind when using those results to compare performance.

For current workload planning, use the hardware and pricing shown in the Compute console.

## Troubleshooting

### My instance was terminated unexpectedly

Check the organization balance and whether the instance had been stopped for more than 10 days. If neither explains the termination, contact Support with the instance ID and approximate time. Cleanup protections do not replace backups or change the documented retention limits.

### I can’t connect to my inference server

Make sure networking is **enabled** and the correct **protocol** (HTTPS/TCP/UDP) is open. Confirm the **endpoint URL**, your **API key** or headers, and that your balance is sufficient.

### SSH fails to connect

Confirm the instance is **Running**, copy its current SSH hostname and username from the console, use the matching private key, and check that your network allows outbound port 22. Verify host-identity warnings before accepting a changed identity.
